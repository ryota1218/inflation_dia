# 01 要求定義書（ドラフト v0.1）

> 工程：要求分析（ウォーターフォール第1工程）
> 状態：**ヒアリング中**（未確定事項あり → 「8. 未確定事項」参照）

## 1. 目的・背景

日常組の企画で使われていた「パーク」の仕組みを Minecraft Java Edition で再現する。
パークを取得すると、ダイヤを掘ったときに手に入る数が増えていく（インフレする）ミニゲームを作る。

## 2. 利用者

| 項目 | 内容 |
|---|---|
| 想定プレイ形態 | マルチプレイ（サーバー） |
| 参加人数 | 未定（Q5） |
| 運営者 | サーバー管理者がゲームの開始・終了を操作する想定（Q2） |

## 3. 機能要求（現時点）

| ID | 要求 | 優先度 | 状態 |
|---|---|---|---|
| F-01 | プレイヤーがパークを取得できる | 必須 | 取得方法は未定（Q1） |
| F-02 | ダイヤ鉱石を掘ったとき、持っているパークに応じてダイヤの数が増える | 必須 | 計算方法は未定（Q3） |
| F-03 | ミニゲームとして開始から終了までを遊べる | 必須 | ルールは未定（Q2） |

## 4. 範囲外（やらないこと）

- まだ決まっていない（今後追記）

## 5. 非機能要求・制約

| ID | 内容 |
|---|---|
| C-01 | **サーバー側だけで動くこと**。プレイヤーに何かを配布したり、クライアントにインストールさせたりしない |
| C-02 | 対象バージョン：Minecraft Java Edition 1.20.x と 1.21.x |
| C-03 | 形式：データパック、またはサーバー側だけで動く Mod／プラグイン（どれにするかは設計工程で決める） |

## 6. 完成の基準

- ミニゲームとして、開始 → パーク取得 → ダイヤ採掘（数が増える） → 終了・結果表示 までを通して遊べること

## 7. 開発の進め方

ウォーターフォール形式で、次の工程を順番に進める。各工程の成果物を承認してから次へ進む。

1. 要求分析（本書）
2. 要件定義
3. 基本設計
4. 詳細設計
5. 実装
6. テスト

## 8. 未確定事項（ヒアリング項目）

- **Q1 パークの内容**：パークの一覧と効果。どうやって取得するか（ランダム／選択／条件達成など）
- **Q2 ゲームの流れ**：開始と終了の条件、勝利条件、個人戦かチーム戦か
- **Q3 インフレの計算方法**：倍率で増えるか加算か、上限はあるか、幸運・シルクタッチとの関係
- **Q4 サーバー環境と対象バージョン**：バニラ／Paper／Fabric のどれか。1.20.x と 1.21.x の全バージョンが必要か
- **Q5 人数**：想定する参加人数
- **Q6 表示言語**：画面に出すメッセージは日本語のみでよいか
