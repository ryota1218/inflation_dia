# 01 要求定義書（ドラフト v0.2）

> 工程：要求分析（ウォーターフォール第1工程）
> 状態：**ヒアリング中**（未確定事項あり → 「9. 未確定事項」参照）

## 1. 目的・背景

日常組の企画で使われていた「パーク（能力）」の仕組みを Minecraft Java Edition で再現する。
パークを取得すると、ダイヤを掘ったときに手に入る数が増えていく（インフレする）ミニゲームを作る。

## 2. 利用者

| 項目 | 内容 |
|---|---|
| 想定プレイ形態 | マルチプレイ（サーバー） |
| 参加人数 | **4人**（将来は人数を増やせるようにしたい） |
| 運営者 | 管理者（あなた）がコマンドでゲームを開始する |

## 3. ゲームのルール概要

- **個人戦**
- 管理者がコマンドを実行するとゲームが始まる
- 開始コマンドの種類で、次の2つのモードを選ぶ

| モード | 勝利条件 |
|---|---|
| 時間制限モード | 制限時間が終わった時点で、ダイヤの総数が最も多いプレイヤーの勝ち |
| 目標個数モード | 目標の個数に最初に届いたプレイヤーの勝ち |

## 4. パーク（能力）

### 4.1 分類

パークは次の5つの系統に分ける。個々のパークの細かい中身は別途定義する（「パーク定義書」を別に作る予定）。

| 系統 | 概要 |
|---|---|
| 敵を倒す系 | 敵（モブ）を倒すことに関係する |
| プレイヤーを倒す系 | 他のプレイヤーを倒すことに関係する |
| ダイヤを掘る系 | ダイヤの採掘に関係する |
| ステータス系 | プレイヤーのステータス（体力・速さなど）に関係する |
| その他 | 上の4つに入らないもの（最も範囲が広い） |

### 4.2 インフレ

- ダイヤを掘ったときの個数は、持っているパークによって増える
- **上限なし**
- 具体的な計算式は、個々のパークの定義の中で決める

## 5. 機能要求

| ID | 要求 | 優先度 |
|---|---|---|
| F-01 | 管理者がコマンドでゲームを開始できる（時間制限モード／目標個数モード） | 必須 |
| F-02 | プレイヤーがパークを取得できる | 必須 |
| F-03 | ダイヤ鉱石を掘ったとき、持っているパークに応じてダイヤの数が増える（上限なし） | 必須 |
| F-04 | プレイヤーごとのダイヤ数を数えて、勝敗を判定できる | 必須 |
| F-05 | ゲームの終了時に結果を表示する | 必須 |
| F-06 | 5つの系統のパークを、あとから追加しやすい仕組みにする | 必須 |

## 6. 範囲外（やらないこと）

- 幸運やシルクタッチ付きのつるはしで掘ったときの対応（そういう使い方は想定しない）
- 日本語以外の表示
- 1.20.1 以外のバージョンへの対応（今回は対象外。将来対応する可能性はある）

## 7. 非機能要求・制約

| ID | 内容 |
|---|---|
| C-01 | **サーバー側だけで動くこと**。プレイヤーに何かを配布したり、クライアントにインストールさせたりしない |
| C-02 | 対象バージョン：**Minecraft Java Edition 1.20.1** |
| C-03 | 形式：データパック、またはサーバー側だけで動く Mod／プラグイン（どれにするかは設計工程で決める） |
| C-04 | 表示言語：日本語のみ |
| C-05 | 4人で問題なく遊べること |

## 8. 完成の基準

- ミニゲームとして、開始 → パーク取得 → ダイヤ採掘（数が増える） → 終了・結果表示 までを通して遊べること
